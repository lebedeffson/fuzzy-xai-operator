# FuzzyXAI — сквозное усиление методологии (главы 1–4)

**Статус:** исходный код доработки и локально проверенный контрольный контур. **Это не подтверждение прохождения всей тестовой матрицы исходного GitHub-репозитория.** Базовый репозиторий: `lebedeffson/fuzzy-xai-operator`, проверенный исходный `main` — `aae7aa717bff913240cbb0026807cd1ccfa67160` (27 августа 2026 года). Изменения не опубликованы в GitHub: интеграция не имеет разрешения на создание ветки (HTTP 403). Основная диссертация, введение и главы 1–4 DOCX не изменялись.

## Что реализовано

Программная часть намеренно **расширяет существующую FuzzyXAI**, а не подменяет её новой игрушечной реализацией. Добавлен механизм `doctoral_certification`, который проверяет *реальный* сохранённый `ExplanationViewModel` существующего фреймворка и вычислительный маршрут его объяснений.

- **Глава 1:** каталог 47 методов из приложения А.5, трёхосевая таксономическая координата `(источник, объект, адресат)`, контроль принадлежности координат каноническому методу.
- **Глава 2:** проверка объяснительного графа, происхождения `E_k`, ссылок на доказательства, правил и активаций, ограничений на функции принадлежности, пересчёт трёх T-норм (minimum/product/Lukasiewicz), явная нехватка свидетельств.
- **Глава 3:** конечный проверяемый выбор минимально достаточного класса `F0`, `F_int`, `F_H`, `F_N_src`, `FML_user`, `FML_audit`; проверка **фактического появления** класса в маршруте; Γ/Δ и пяти компонент риска, блокировка критического разрыва, защита от NaN/Inf и некорректных весов.
- **Глава 4:** проверяемый граф происхождения, обнаружение циклов и обрывов, три уровня детализации, SHA256-снимок сертификатора, сохранённый сертификат, повторная проверка после исправлений, пакетная обработка и локальный HTML-отчёт. У существующего `DiagnosticService` сохраняется ответственность за полноценные планы восстановления и повторную сертификацию маршрутов.

Транзакционный установщик до записи проверяет все восемь нужных исходных файлов и Python/TOML-синтаксис; если якорь устарел, **отказывается применять изменения**, а не заменяет случайный фрагмент.

## Программный интерфейс для настоящей модели

```python
from fuzzyxai import FuzzyXAI, verify_certificate
from fuzzyxai.doctoral_report import render_doctoral_report

fx = FuzzyXAI.wrap(fitted_sklearn_model)
result, cert = fx.explain_one_certified(
    observation, object_id='case-001', feature_names=feature_names,
    taxonomy={
        'method_id': 'm01',
        'source': 'intrinsic', 'object': 'features', 'audience': 'auditor',
        'canonical_configuration': 'Линейные и логистические модели',
    },
    representation={'profile': ['u_num', 'u_ling'], 'selected_class': 'F0'},
)
assert verify_certificate(cert)['valid']  # доказательство повторяемости ПРОВЕРКИ
render_doctoral_report(cert, 'out/report.html')
print(cert['decision']['status'])  # при отсутствии нечётких правил обычно НЕ valid
```

Важное ограничение: обычная LogisticRegression **не превращается автоматически в сертифицированную нечёткую систему**. Если нет реально вычисленных правил, функций принадлежности, выполненного выбора класса и остальных необходимых каналов, статус будет `insufficient_evidence`. Это корректное поведение.

## Массовый аудит

```bash
fuzzyxai-certify batch \
  --input-dir ./serialized_explanations \
  --taxonomy ./taxonomy.json \
  --representation ./representation.json \
  --out-dir ./batch_report
```

В каталоге должны быть отдельные JSON-объяснения, а не `certificate.json`. Из пакета выходят `batch_summary.json` и `batch_cases.csv` — только статусы, коды ошибок и хеши, без сырых объектов. Пропущенные/нечитаемые записи не считаются успешно сертифицированными.

## Научные границы результата

- `valid` означает **согласованность объявленного и наблюдаемого вычислительного маршрута**, а не истинность прогноза, причинную идентифицируемость, клиническую безопасность или превосходство над baseline.
- SHA256 сертификата и SHA256 кода сертификатора позволяют проверять согласованность байтов; они **не удостоверяют автора и не заменяют цифровую подпись**.
- Класс представления выбирается по конечной политике сложности; это **не доказательство глобальной минимальности для всех возможных нечётких систем**.
- Диагностическое сечение в сертификате покрывает его **локальные обязательства**. Полноценные графовые ремонты выполняет существующий `fuzzyxai.diagnostics.DiagnosticService`, не сертификатор.
- Демо-данные контролируемые и для признания в качестве полного доказательства требует явного разрешения. Невыполненные этапы реальной предметной валидации указаны в `docs/DOCTORAL_CONFORMANCE_1_TO_4.md`.

## Конфиденциальность и эксплуатация

Сертификат содержит хеши, идентификаторы и описания доказательств; известные поля сырого текста, изображений и массивов атрибуции маскируются. **Это не полноценная система обезличивания**: названия объектов, сообщения экспертов, произвольные метаданные, диагностические причины и другие поля могут содержать персональные сведения. Не публикуйте сертификаты с медицинскими или корпоративными данными без отдельной проверки состава полей. Статический HTML работает без внешних серверов и не исполняет непроверенный HTML из входного содержимого.
