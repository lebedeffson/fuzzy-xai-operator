# Совместное обучение интервальной нечёткой модели второго типа (IT2)

## Постановка и ограничение новизны

В предыдущем варианте `NativeIntervalType2Logistic` сначала обучалась Type-1 логистическая
модель над нечёткими термами, а затем вокруг её функций принадлежности
строилась FOU на основании бутстрепа. Отсюда не следовало, что **обучение
действительно использует неопределённость функций принадлежности**.

`JointIntervalType2Logistic` устраняет именно эту ограниченность: оптимизируются
в одном объекте `scipy.optimize.minimize(method='L-BFGS-B')`:

- коэффициенты правил `d_j` и свободный интерсепт `b`;
- положения двух границ плечевой функции принадлежности `l_j`, `r_j`;
- ненулевые полуширины интервалов неопределённости `u_{l,j}`, `u_{r,j}`.

Выбор **пяти** исходных признаков и определение исходных бутстреп-интервалов
по-прежнему происходят на обучающей части. Поэтому это совместное обучение
**параметров нечёткой модели**, но не end-to-end обучение всех её этапов,
включая исходный выбор признаков. Оптимизация нелинейна и не выпукла,
глобальная оптимальность не доказана.

## Точная параметризация

Для каждого выбранного признака вводятся два сопряжённых терма:

```text
mu_high(x; l,r) = clip((x-l)/(r-l),0,1)
mu_low(x) = 1 - mu_high(x)
```

В действительности `l` и `r` описываются диапазонами. Нижняя функция
принадлежности LMF берётся при максимально правых границах, верхняя UMF —
при максимально левых. Диапазоны привязаны к исходному размаху `g=r0-l0`,
с оптимизируемым смещением центров не более `0.12g` и шириной
`[0.012g,0.16g]`; всегда обеспечивается `left_max < right_min`.
Это **ограничения модельного класса, не доверительные интервалы**.

Поскольку `mu_low` и `mu_high` связаны, их вклады не следует считать
независимыми. Для коэффициента `d_j`:

```text
z_lower = b + sum_j min(d_j * LMF_j(x), d_j * UMF_j(x))
z_upper = b + sum_j max(d_j * LMF_j(x), d_j * UMF_j(x))
p_lower = sigmoid(z_lower);  p_upper = sigmoid(z_upper)
p_point = (p_lower + p_upper)/2
```

Коэффициент низкого терма выбран нулевым, его константная часть поглощена
интерсептом. Так устраняется тривиальная неидентифицируемость параметров.
Результат сериализуется в `IT2FuzzyLogit`, и независимый `verify_it2_receipt`
восстанавливает численное свидетельство тем же математическим контуром.

## Функция потерь

Предопределённый исследовательский функционал содержит:

1. Среднюю бинарную перекрёстную энтропию для `p_point`.
2. Худшую бинарную перекрёстную энтропию внутри FOU: для положительного
   класса используется `p_lower`, для отрицательного — `p_upper`.
3. L2-регуляризацию весов правил, смещений центров и отклонений ширины
   FOU от бутстреп-инициализации.

Коэффициенты функционала фиксируются кодом до работы с `calibration`,
`policy` и `test`. При наличии локального минимума оптимизатор может его
достичь, не доказывая глобального превосходства. В диагностике сохраняются
исходное/конечное значения потерь, причина остановки и SHA256 модели.

## Протокол сравнения (без утечек)

WDBC разбивается на четыре **непересекающиеся внутри одного seed** части:
`train=341`, `calibration=79`, `policy=35`, `test=114`.
Сравниваются три варианта на **одинаковых строках теста**:

- `type1_matched`: исходная Type-1 с собственным split conformal и
  порогом отказа, выбранным на `policy` для приближения к доле ответов joint IT2;
- `bootstrap_it2`: прежняя Type-2 модель с FOU после обучения Type-1;
- `joint_it2`: совместно обученная модель и собственная split conformal калибровка.

Для каждого метода сохраняются actual accepted, errors, FN, ROC-AUC,
Brier, эмпирическое marginal set coverage и пообъектные CSV. Расхождение
долей автоматических решений на **тесте** явно фиксируется: это не
искусственно равные проценты и не причинный эффект метода.

Дополнительно проводится **синтетическое искажение измерений** Gaussian
`std = 0.10` и `0.25` обучающего стандартного отклонения. Разбиения,
конформные пороги и политика отбора при этом не изменяются. Синтетическое
искажение **не заменяет испытания на независимом внешнем наборе**, и
теоретическое conformal-покрытие при таком сдвиге не гарантируется.

Пять seed используют повторно один исходный WDBC — их 570 строк теста
**не являются независимыми клиническими наблюдениями**. P-value превосходства
из этих пяти повторных разбиений без корректного учёта зависимости
не вычисляется.

## Воспроизведение

```bash
python -m pytest -q tests/test_doctoral_joint_it2.py
python -m experiments.doctoral_joint_interval_type2 \
  --out reports/chapter5/joint_type2 --bootstrap 16 --max-iter 300 \
  --seeds 17 42 73 123 2026
```

CI: `.github/workflows/doctoral-joint-type2.yml`, Python 3.11 и 3.12.
Пока реальная CI не завершена, не цитируйте исследовательские метрики
как проверенные; результаты экспериментальной репликации прикладываются
отдельным манифестом SHA256. Не следует смешивать исходные материалы главы 5
по ЭКГ с WDBC: это разные предметные наборы.

## Отдельная проверка сходимости и числовых свидетельств

CI теперь требует `optimizer_success=True` для **каждого** из пяти разбиений и отвергает завершение с кодом `TOTAL NO. OF ITERATIONS REACHED LIMIT`. Пообъектный CSV сохраняет `fou_probability_lower`, `fou_probability_upper`, `fou_width`, `fou_crosses_threshold` и `blocked_reason` для независимого анализа принятия решений. Совпадение/расхождение ошибок между методами проверяется по исходным `row_id`, а не только по средним значениям.
