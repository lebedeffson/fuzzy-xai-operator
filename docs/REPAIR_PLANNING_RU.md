# Планирование восстановления

`ActionableRepairPlanner` получает граф, диагностические нарушения и уже проверенный
разрез. Он не получает Gold-разметку, mutation log или скрытые эталонные ответы.

Каждый `RepairStep` содержит provider, операцию, цель, предусловия, зависимости,
проверяемые постусловия, rollback и стоимость. Предлагаемые значения представлены
ссылкой вида `registry://component`, а не копируются из `route.expected`.

По умолчанию создаётся только план. Выполнение возможно лишь при одновременном наличии:

* `repair_mode="execute"`;
* `RepairExecutionContext`;
* `allow_external_changes=True`;
* явно одобренного `step_id`;
* зарегистрированного обработчика операции.

После исполнения успешность не принимается на веру: выполняется полная повторная
сертификация.
