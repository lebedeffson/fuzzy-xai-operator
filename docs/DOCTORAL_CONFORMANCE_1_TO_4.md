# Матрица соответствия программного FuzzyXAI материалам глав 1–4

| Требование диссертации | Зависимость от существующего кода | Что проверяет новая подсистема | Проверка и ограничение |
|---|---|---|---|
| **Глава 1. Три оси XAI** | Классификация источника / объекта / адресата | `doctoral_catalog.py`, `Taxonomy`, 47 строк А.5 | Контроль `m01..m47`, сторонние методы `self_declared`, без верификации истинности названия метода |
| **Глава 2. Объяснительный объект** | `ModelExplanationResult`, `ExplanationGraph`, `ExplanationClaim` | Идентификаторы, существование графовых связей, отсутствующие каналы и честный status | Проверка структуры и доказательных ссылок, но не причинная идентифицируемость |
| **Глава 2. Лингвистические термы и правила** | `MembershipPolicy`, `FuzzyRuleActivation` | Параметры треугольных ФП, происхождение, численная T-норма | Только на измеренных входных степенях; нет утверждения о глобальной fidelity |
| **Глава 2. Согласование Γ** | `alignment`, `ExplainPlan` | Применимость, доверенный диапазон, контроль против значений компонентов | Семантическая валидность каналов требует предметной экспертизы |
| **Глава 3. Выбор F-класса** | `selection/pareto_selector`, разные классы неопределённости | Конечная система покрытия, явное исполнение `selected_representation`, запрет скрывать конфликт | Затраты класса — заданный порядок сложности, не фактически измеренные CPU/память |
| **Глава 3. Редукция Δ** | `ReductionPolicy`, `reduction` | Отсутствие «нуля» при missing, проверка epsilon и согласованности | Погрешность должна быть измерена предметным оператором |
| **Глава 3. Риск ρ** | `risk_observer`, `risk_function`, `risk.policy` | Ровно пять P19 слагаемых, сумма весов 1, запрет NaN/Inf, пороговая политика | Неполный риск не становится валидным через нормировку по наличным значениям |
| **Глава 3. χ_R и χ_R_crit** | структурные диагностики | Отдельные флаги; критический разрыв принудительно даёт `block` | Для не критического разрыва возможны другие решения при учёте его в риске |
| **Глава 4. След происхождения** | `view_model.trace`, граф свидетельств | SHA входа/плана/модели, версия датасета, объект, время, DAG, связи с утверждениями | Формат SHA проверяется, но исходные сырые данные могут быть недоступны для повторного хеширования |
| **Глава 4. Диагностика и ремонт** | `DiagnosticService`, план восстановления | Сводка ошибок и **локальное** минимальное покрытие обязательств сертификатора | Не заменяет минимальный разрез и re-certification в `DiagnosticService` |
| **Глава 4. Воспроизводимость** | экспорт JSON / CI / тесты | Детерминированный сертификат, SHA кода сертификатора, replay, батч, HTML | Не является подписью или полной трассировкой всего программного стека |

## Условия допуска в диссертационную апробацию

Для любого сценария требуется как минимум: источник входов и контроль его версии; явная предметная модель; протокол обучения/оценки без утечек; исходные предсказания; наблюдаемые объяснительные каналы; вычисленные классы F; проверенный риск и действие; доказательный граф; контрольные суммы; результаты сравнений с эквивалентными по доступной информации baseline. Отсутствующий канал фиксируется как недостаточность, а не восстанавливается выдуманным числом.

### Что фактически протестировано здесь

- Самостоятельное ядро сертификации: unit, negative, replay, HTML, batch, fixture и корректность скрипта применения.
- **Не выполнено в текущем окружении:** установка полного исходного GitHub checkout с патчем; весь исходный набор pytest/CI репозитория; полная проверка внешних моделей, Docker; доступность и deployment DubnaXAI.ru.
- **Не заявляется:** медицинская оценка по PTB-XL и внешняя валидность GIS/биометрии, пока они не проведены с конкретными наборами данных.

## Риски внедрения и независимая проверка

1. **API drift**: `install_fuzzyxai_upgrade.py --check` должен найти ровно свои исходные фрагменты; при несовпадении он прекращает выполнение.
2. **Численная совместимость**: исправление обработчиков NaN/Inf и отрицательных весов может превратить старые молчаливые результаты в явные исключения; требуется прогнать legacy-регрессию.
3. **Неполные модели**: сертификатор строже исходного внешнего адаптера; «недостаточно свидетельств» — ожидаемый статус, а не ошибка расчёта.
4. **Происхождение**: SHA входных файлов не пересчитывается из исходных данных, если предоставлен только агрегированный `ExplanationViewModel`.
5. **Масштаб графа**: DAG проверяется итеративно; при массовом обучении нужны профилирование runtime и ограничение размера сертификата.
6. **Валидация клинических задач**: запрещено трактовать снижение пропусков контролируемого правила как доказательство медицинской безопасности.

### Протокол v5: реализовано, но не подтверждено полной CI

В v5 добавлен нативный прогноз \(p(x)=\sigma(b+\sum_r w_r\mu_r(x))\), контроль замыкания правил на реальную модель, измерение изменения прогноза при редукции, пять повторных исследовательских WDBC-разбиений и 114 пройденных локальных тестов. Описательные метрики и ограничения приведены в `docs/DOCTORAL_V5_CHAPTER5_RESULTS_RU.md`. Четыре теста настоящей интеграции `FuzzyXAI.wrap()` и часть прикладных тестов ожидают полный исходный checkout. Публикация в GitHub не произведена; исходная диссертация не менялась.
